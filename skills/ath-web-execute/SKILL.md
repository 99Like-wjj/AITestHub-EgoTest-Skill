# AITestHub 本地 UI 执行

当前 AI 自主理解业务目标、选择现场验证方式并作出结论。Ego 提供浏览器原语。本地工具保存事实、固定引用、传输和恢复。用例与报告在 AITestHub 展示。

优先使用宿主已配置的AITestHub官方MCP；私有落盘/原字节传输由可信host注入端口，不让模型代管Key或另造HTTP鉴权。

先运行 `node scripts/tool.mjs tool-info`，核对包完整性与运行时。实际安装、当前会话加载、MCP联通和Ego可用性分别验证。当前写入使用v2交付契约和注入式可信宿主。缺少可信宿主时可运行离线结构校验。

已有本地 UI 执行可按 [独立归档](references/independent-archives.md) 整理和提交。归档不领取计划、不执行目标、不修改正式范围。

执行前读 [v2固定范围与交付](references/v2-delivery.md) 和 [本地固定执行命令](references/local-workflow.md)，可信宿主入口为 `runV2LocalCommand`。涉及中断再读 [恢复契约](references/recovery-contract.md)。接入真实宿主前读 [Ego与安全条件](references/ego-safety.md)。v1账本保留原文件，按对应原包核对。

1. 核对用户授权的项目、环境、账号及允许副作用，确认共同host和实际Ego版本指南。采用当次指南的停止/接管规则；本项目自测的特殊空间重建授权不扩成默认用户授权。
2. 用 `ath_ui_executions` 领取已批准计划修订，或已准备UI直接复测的固定group。先持久化原 `localExecutionId`，再领范围；计划用planRevisionId、复测用groupId。保存原scope及摘要；缺口如实说明，不自动换版、扩范围或执行API。
3. 按冻结范围验证业务目标。根据现场选择入口、工具、操作顺序和取证时机。参考步骤可用作导航线索，可选择等价路径或合并观察。在 [结果与证据标准](references/result-quality.md) 查判定标准和取证经验。
4. 对可能写入SUT的动作，先落在途意图再实际执行；动作已发但响应未知，先只读核对真实状态。工具不会重放该动作。用户接管/权限丢失/提示要求停止时停止相关执行，保留已发生事实。
5. 保存真实操作、观察、可核查的结论和原始证据。按实际关系关联业务断言、冻结步骤或现场操作，并明确未确认项。选择适合现场的证据类型和取证数量。按批次准备低频进度，进度与结果独立。额外发现走平台独立问题能力。
6. 持续按真实结果准备v2批次，保留每批原ID/完整JSON/逐项回执；每批最多100个证据身份，单Case大引用用descriptor/refs片段，文件仍完整PUT。实际结束、原轮明确恢复与累计seal分别准备和提交，不能用传输批次假装执行结束；未执行必须有真实原因，不能藏未知动作。
7. 恢复原run/原命令/原文件身份，不重跑已经发生或未知副作用；修复后的重新验证领取新复测run，保留旧结论。交付完成、原始判断、人工最终结论、缺陷和复测状态分别说明，不自动关闭缺陷。

输出本轮固定范围、执行结果及其依据、证据缺口、原回执与当前交付、平台链接及真实未验证项。模型、平台与 SUT 的鉴权凭据各走原有安全入口。

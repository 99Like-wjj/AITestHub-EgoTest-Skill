# AITestHub 本地 UI 执行

当前 AI 负责理解业务目标、现场导航和结论；Ego 负责浏览器原语。本地工具保存事实、固定引用、传输和恢复，不规划点击、不调用另一模型、不自动判通过。人友用例与报告只在平台展示，不生成独立 HTML。

优先使用宿主已配置的AITestHub官方MCP；私有落盘/原字节传输由可信host注入端口，不让模型代管Key或另造HTTP鉴权。

先运行 `node scripts/tool.mjs tool-info`，核对包完整性与运行时。它不证明已安装、当前会话已加载、MCP联通或Ego可用。0.2.1使用v2交付候选和注入式可信host；其真实联通另验，不继承0.1.0的小范围实测结论。缺host时保留本地校验，不自造HTTP或把Key贴聊天。

已有本地 UI 执行可按 [独立归档](references/independent-archives.md) 整理和提交。归档不领取计划、不执行目标、不修改正式范围。

执行前读 [v2固定范围与交付](references/v2-delivery.md)，可信host入口为 `runV2LocalCommand`。涉及中断再读 [恢复契约](references/recovery-contract.md)；接入真实宿主前读 [Ego与安全条件](references/ego-safety.md)。旧journal必须使用保留的原0.1.0包恢复，不清空、换ID或静默迁移。

1. 核对用户授权的项目、环境、账号及允许副作用，确认共同host和实际Ego版本指南。采用当次指南的停止/接管规则；本项目自测的特殊空间重建授权不扩成默认用户授权。
2. 用 `ath_ui_executions` 领取已批准计划修订，或已准备UI直接复测的固定group。先持久化原 `localExecutionId`，再领范围；计划用planRevisionId、复测用groupId。保存原scope及摘要；缺口如实说明，不自动换版、扩范围或执行API。
3. 默认串行按固定Case目标执行。无需预写点击步骤；依据现场页面决定路径。每项保存实际观察，关键状态截图要真实捕获并查看。动作成功、HTTP200、hash或上传成功不能代替业务通过。
4. 对可能写入SUT的动作，先落在途意图再实际执行；动作已发但响应未知，先只读核对真实状态。工具不会重放该动作。用户接管/权限丢失/提示要求停止时停止相关执行，保留已发生事实。
5. 持续记录结果与证据索引，约每十Case准备一次低频进度；进度与结果/报告独立。缺截图要记录原因和对结论的影响，不能补造。额外发现走平台独立问题能力，不塞入固定scope。
6. 持续按真实结果准备v2批次，保留每批原ID/完整JSON/逐项回执；每批最多100个证据身份，单Case大引用用descriptor/refs片段，文件仍完整PUT。实际结束、原轮明确恢复与累计seal分别准备和提交，不能用传输批次假装执行结束；未执行必须有真实原因，不能藏未知动作。
7. 恢复原run/原命令/原文件身份，不重跑已经发生或未知副作用；修复后的重新验证领取新复测run，保留旧结论。交付完成、原始判断、人工最终结论、缺陷和复测状态分别说明，不自动关闭缺陷。

输出只列本轮固定范围、执行/未执行、证据缺口、原回执与当前交付、平台受权链接及真实未验证项。模型/Key/SUT登录凭据分别走安全通道，不进入工具参数、账本、报告或 stdout。工具的秘密模式检测只是辅助，不能承诺识别所有个人/业务资料。
